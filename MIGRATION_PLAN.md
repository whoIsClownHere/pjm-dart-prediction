# План миграции проекта: от регрессии DART к классификации спайков

Инструкция для агента. Работать **строго по фазам**. Каждая фаза заканчивается
контрольной точкой: агент показывает результат и останавливается, пока человек не
подтвердит переход к следующей.

Методология и обоснование — в `README.md`. Здесь только порядок работ и критерии
приёмки.

---

## Общие запреты

Действуют на протяжении всех фаз.

1. **Не создавать параллельный пайплайн.** Все изменения — правки существующих
   модулей. Если кажется, что проще написать `features_v2.py` рядом со старым —
   остановиться и спросить.
2. **Не применять к колонке `dart` ни одной операции, кроме `da_lmp - rt_lmp`.**
   Никакого clip, никакого dropna по значению, никакой фильтрации по порогу. Все
   преобразования — в отдельной колонке `dart_feat`.
3. **Не добавлять признаки сверх списка §4 README.** Ни «на всякий случай», ни ради
   улучшения метрики. Убрать лишнее — половина задачи.
4. **Не запускать модель на тестовом периоде до фазы 6.** Тестовый период читается
   ровно один раз.
5. **Не заменять логистическую регрессию на что-то более гибкое**, даже если валидация
   улучшится. Обоснование в README §7.
6. **Не выдумывать имена колонок внешних датасетов.** Сначала выгрузить один день,
   напечатать `df.columns` и `df.dtypes`, показать человеку, потом писать мердж.
7. Не переименовывать репозиторий и не трогать git history без отдельной просьбы.

## Фаза 5 — Модели

- Две логистические регрессии (`y_pos`, `y_neg`), обучение только на train.
- Стандартизация внутри пайплайна sklearn, `class_weight="balanced"`, L2.
- Удалить или пометить deprecated регрессионные модели Ridge/LightGBM на `dart` —
  они больше не являются основным трактом. Решение о полном удалении принимает человек.
- `score_backtest` (MAE/RMSE) больше не критерий успеха. Добавить `score_spikes`
  (precision / recall / F1 по каждой стороне) и `score_pnl` (кумулятивный P&L, Sharpe,
  max drawdown, число трейдов).

Приёмка: модели обучаются, на валидации precision по INC-стороне отличима от базовой
частоты класса. На тест не смотреть.
